# Чернограм — постоянная дорожная карта

> Этот файл — рабочая память проекта. Перед любой правкой сначала прочитать его целиком. После каждой законченной задачи обновить разделы «Сделано», «Сейчас» и «Дальше».

## Главное правило разработки

1. Не трогать уже работающие функции, если задача их не касается.
2. Сначала менять существующие файлы и компоненты; новые добавлять только при реальной необходимости.
3. Перед выпуском проверять базовый пользовательский путь: запуск → список чатов → открытие чата → текст → файл → повторный вход → звонок → обновление.
4. Любая тяжёлая работа выполняется после показа локального интерфейса, а не до него.
5. История и метаданные хранятся локально отдельно от тяжёлых медиа.
6. Android и Windows развиваются синхронно. iOS не трогать без отдельной команды.
7. После каждого релиза фиксировать здесь версию, выполненные пункты, известные проблемы и следующий шаг.

## Что мы строим

Чернограм — локально-ориентированная коммуникационная платформа: чаты, звонки, P2P-передача файлов, общие папки между людьми и устройствами, музыкальный плеер и локальный агент в одном приложении без рекламы и обязательного VPN.

Главная идея: данные принадлежат пользователю. Чат открывается из локальной истории моментально, сеть подключается незаметно в фоне, а тяжёлый контент загружается только по запросу.

## Обязательный пользовательский сценарий

1. Приложение запускается быстро.
2. Главная и список чатов показываются сразу.
3. Существующий чат открывается из локального кэша без ожидания сети и медиа.
4. Последние 30–50 сообщений видны моментально; старые подгружаются вверх постранично.
5. Фото отображаются через миниатюры; видео, музыка и документы не загружаются до нажатия.
6. Текст можно написать без сети; сообщение становится в локальную очередь и отправляется после восстановления связи.
7. После выхода на главную повторный вход в чат происходит мгновенно.
8. Вложения можно открыть, сохранить, передать системным меню и удалить.
9. Звонок устанавливается быстро, имеет собственную мелодию и корректно переживает краткий обрыв сети.
10. Обновление Windows и Android не удаляет профиль, историю и настройки.
11. Установка и обновление Windows не должны показывать пользователю консольные окна, PowerShell, CMD или служебные команды.

## Архитектурные принципы

- UI никогда не ждёт сеть перед навигацией.
- Соединение, синхронизация и медиа работают фоновыми задачами.
- Один постоянный личный чат формируется из пары ID пользователей.
- Повторное открытие контакта всегда ведёт в тот же личный чат.
- Текст и метаданные сообщений не содержат Base64 тяжёлых файлов.
- Медиа хранится в управляемом локальном кэше с лимитом и политикой очистки.
- Переподключение использует backoff и не обновляет интерфейс каждые несколько секунд.
- Изменения интерфейса делаются компактно, без лишних рамок и декоративных элементов, отнимающих место.
- Рабочие элементы защищаются регрессионными smoke-тестами.
- Все служебные процессы Windows запускаются скрыто и ведут журнал в файл вместо открытия консоли.
