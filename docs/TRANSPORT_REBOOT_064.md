# Чернограм 0.64 — перезапуск ядра связи

Статус: эксперимент. Эта ветка не публикуется пользователям и не заменяет текущий транспорт до прохождения испытаний.

## Причина

Текущий транспорт на публичных ntfy relay и общем TURN не обеспечивает гарантированную доставку сообщений, устойчивый сигналинг звонков, фоновую работу и возобновляемую передачу файлов.

## Выбранное направление

Для первого независимого испытания используется официальное ядро SimpleX Chat:

- SMP для асинхронной доставки и store-and-forward;
- локальная база на каждом устройстве;
- подтверждаемая доставка событий;
- XFTP как дальнейшая основа передачи файлов;
- WebRTC-звонки рассматриваются только после доказанной стабильности сообщений.

SimpleX-код не копируется в Dart и криптография не переизобретается. На первом этапе используется официальный Node.js binding к тому же нативному ядру, которое предоставляет функции `chat_migrate_init`, `chat_send_cmd_retry` и `chat_recv_msg_wait` мобильным и desktop-клиентам.

## Этап 1. Независимый сетевой пробник

GitHub Actions поднимает два клиента с разными локальными базами:

1. создаёт профили Alice и Bob;
2. создаёт одноразовое приглашение;
3. устанавливает контакт через публичную SimpleX-сеть;
4. отправляет последовательность сообщений с уникальными идентификаторами;
5. измеряет время фактического появления каждого сообщения у Bob;
6. полностью останавливает и закрывает Bob;
7. отправляет сообщения, пока Bob выключен;
8. повторно открывает ту же локальную базу Bob;
9. проверяет доставку всей офлайн-серии без потерь и дублей;
10. сохраняет JSON-отчёт и полный журнал.

Успехом считается только 100% доставка. Локальное отображение сообщения у отправителя успехом не считается.

## Этап 2. Android bridge

После зелёного этапа 1:

- подключить официальную `libsimplex.so` через JNI;
- создать узкий Flutter MethodChannel/EventChannel;
- оставить текущий интерфейс Чернограма;
- заменить только создание контакта, исходящие команды и входящие события;
- включить Android foreground service для приёма событий;
- добавить реальные состояния `создано / принято ядром / доставлено / прочитано`.

## Этап 3. Испытание на устройствах

Минимальные условия допуска:

- Wi‑Fi → LTE, LTE → LTE и разные операторы;
- 500 текстовых сообщений без потерь;
- получение после закрытия приложения и перезагрузки телефона;
- 20 последовательных личных звонков после отдельного исправления звонков;
- файл 100 МБ с возобновлением и совпадающим SHA‑256.

## Ограничения

- групповые видеозвонки не переносятся до выбора SFU;
- старый ntfy-транспорт остаётся только в опубликованной версии и не используется как доказательство нового ядра;
- новые декоративные функции заморожены до прохождения сетевых тестов;
- код SimpleX распространяется по AGPLv3, поэтому интеграция должна сохранять лицензионные уведомления и доступность соответствующего исходного кода.
