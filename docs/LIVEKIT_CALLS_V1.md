# LiveKit Calls v1

Этот этап добавляет независимый медиаканал LiveKit, короткоживущие токены из Python broker и отдельный экран проверки Android ↔ Windows. Существующие звонки на `flutter_webrtc` пока не заменяются: новый канал сначала проверяется отдельно и не влияет на установленную версию.

## Локальный запуск

1. Скопируйте файл окружения:

```bash
cp .env.livekit.example .env.livekit
```

2. В `.env.livekit` укажите LAN IP компьютера, доступный телефону. Значения `LIVEKIT_API_KEY` и `LIVEKIT_API_SECRET` для локального теста должны совпадать с `infra/livekit/livekit.yaml`.

3. Запустите сервер, Redis и broker:

```bash
docker compose --env-file .env.livekit -f docker-compose.livekit.yml up --build
```

4. Проверьте broker:

```bash
curl http://127.0.0.1:8090/healthz
```

5. В Чернограме откройте меню → **Тест LiveKit**. На Windows и Android укажите:

- одинаковую комнату;
- разные `Identity`;
- адрес broker через LAN IP компьютера, например `http://192.168.1.20:8090`;
- одинаковый ключ broker из `.env.livekit`.

После подключения микрофон включается, камера запускается отдельной круглой кнопкой. Красная кнопка немедленно разрывает соединение.

## Порты локального стенда

- `7880/TCP` — LiveKit WebSocket/API;
- `7881/TCP` — резервный WebRTC TCP;
- `8090/TCP` — Python broker;
- `3478/UDP` — встроенный TURN/UDP;
- `50000–50100/UDP` — WebRTC media.

Эти порты должны быть разрешены в локальном брандмауэре Windows. Android и компьютер должны видеть друг друга в одной сети без гостевой изоляции Wi‑Fi.

## Безопасность и следующий этап

API secret LiveKit остаётся только на сервере. Приложение получает от broker токен входа в конкретную комнату со сроком жизни 30 минут. Broker не хранит переписку, медиа или содержимое звонка.

Перед реальным интернет-развёртыванием необходимо заменить тестовые ключи, включить `WSS/TLS`, назначить домен, настроить внешний IP и собственный TURN с TLS. После успешного теста Android ↔ Windows этот клиент можно подключить к штатным кнопкам входящего и исходящего звонка, затем добавить Android Telecom и push-пробуждение.
